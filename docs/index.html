What the system demonstrates

The project treats language learning as an auditable product workflow: requirements are explicit, data contracts are testable, state transitions are controlled and ambiguous outputs are routed to human review.

01

Workflow design

Translates an ambiguous learning process into requirements, schemas, state transitions and quality gates.

02

Privacy by design

Separates public engineering evidence from private diaries, conversations, notebooks and Anki collections.

03

Calibrated review

Uses frozen predictions, manual-gold comparison, error classes and explicit approval rather than unsupported accuracy claims.

Governed learning flow

Each stage preserves provenance and makes uncertainty visible. Automation supports the learner; it does not silently replace human judgement.

One system, two boundaries

The public repository makes engineering decisions inspectable without exposing the content that gives the learning material its personal relevance.

Public engineering evidence

  • Requirements and protocol
  • Schema-defined data contracts
  • Python CLI and validators
  • Synthetic fixtures and tests
  • Privacy-safe aggregate findings

Private learner workspace

  • Oral diary conversations
  • Complete source archive
  • Manual and stable notebooks
  • Anki collections and exports
  • Personal review history
